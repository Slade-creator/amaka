# Model Card — AMAKA Hybrid Load Forecaster

## Overview

| Item | Detail |
|---|---|
| Intended use | Decision support for facility energy managers: short-term load visibility, peak alerts, generator-dispatch planning |
| Model type | Two-stage hybrid: XGBoost regressor + residual LSTM |
| Horizon | 1 hour ahead (operational replay in this prototype) |
| Sites | 6 Zambian military facilities (synthetic load) |
| Output | Point forecast (kW) + 95% interval derived from held-out residuals |
| Explainability | TreeSHAP contributions per prediction (kW) |
| Version | `hybrid-xgb-lstm-v0.1` (Sprint 3 prototype) |

## Data

- **Weather:** hourly historical observations from the Open-Meteo Archive API for each
  site's coordinates (temperature, relative humidity, precipitation, cloud cover,
  shortwave radiation, wind speed), 2024-01-01 to 2025-12-31, Africa/Lusaka time.
- **Facility load:** synthetic hourly load generated by `src/generate_load.py` from real
  weather, per-site base load, occupancy cycles, HVAC, lighting, rooftop PV
  self-consumption, Zambian public holidays, synthetic readiness codes, faults and
  maintenance windows. This is a proxy because real installation data is restricted.
- **Readiness:** synthetic operational-readiness codes 1–4 (1 = exercise surge,
  4 = routine), with per-code multipliers and event durations.
- **Features (23):** readiness code, six weather variables, missing/imputation and
  disruption flags, calendar sin/cos encodings (hour, day of week, month), load lags
  (1 h, 2 h, 24 h, 168 h), and 24-hour rolling mean/std.

### Splits (chronological, no shuffling)

| Split | Period | Purpose |
|---|---|---|
| Train | 2024-01-01 – 2024-12-31 | Fit XGBoost, scalers, LSTM |
| Validation | 2025-01-01 – 2025-06-30 | Early stopping, model selection |
| Test | 2025-07-01 – 2025-12-31 | All reported metrics, dashboard replay |

Scaling is fit on the training split only. The test period is never used for fitting or
early stopping.

## Stage 1 — XGBoost

- 300 trees, max depth 6, learning rate 0.05, subsample 0.8, colsample 0.8.
- Objective: squared error; per-site model because base loads range from 1,000 to
  3,000 kW.
- Learns non-linear interactions between weather, calendar, readiness and lag features.

## Stage 2 — Residual LSTM

- 168-hour input window (one week) of the 23 scaled features.
- 2 LSTM layers, 32 hidden units, dropout 0.2, linear head 32→16→1.
- Target: residual `actual − XGBoost` at the next hour, standard-scaled on train.
- Adam, lr 1e-3, batch 128, max 20 epochs, early stopping (patience 5), gradient clipping.
- Final prediction: `XGBoost + inverse-scaled LSTM residual`.

## Held-out performance (2025-H2)

| Site | XGB RMSE | Hybrid RMSE | Hybrid MAE | MAPE | Persistence MAE | Seasonal-naive MAE |
|---|---:|---:|---:|---:|---:|---:|
| Arakan | 87.7 | 87.7 | 52.3 | 2.78% | 134.6 | 206.4 |
| Kohima | 73.1 | 73.1 | 53.6 | 2.52% | 155.7 | 230.2 |
| Makeni | 37.0 | 37.0 | 27.4 | 2.63% | 82.4 | 116.6 |
| Mikango | 52.5 | 52.4 | 35.4 | 2.77% | 97.5 | 146.1 |
| Peter Zuze | 88.1 | 88.1 | 67.3 | 2.44% | 215.0 | 297.0 |
| Tug Argan | 52.9 | 52.8 | 39.1 | 2.57% | 112.9 | 184.7 |

**Interpretation.** The hybrid beats persistence and seasonal-naive baselines by a wide
margin. The residual LSTM improves MAE by only ~0.1 kW at a one-hour horizon, because
lag-1 load already explains most of the variance and the residual is close to noise.
The architecture is implemented and evaluated; longer-horizon and surge-weighted variants
are Sprint 4 work. This limitation is surfaced in the dashboard rather than hidden.

## Error behaviour

- Largest errors occur during synthetic readiness-1 exercise surges and fault events,
  which are rare and under-represented in training.
- MAPE is unstable near zero load; RMSE and MAE are the primary metrics.
- Intervals are constant-width (`±1.96σ` of held-out hybrid residuals), not
  horizon-aware. A production system should use quantile or conformal intervals.

## Intended use and non-use

**Intended:** planning and situational awareness inside a demo or research setting;
illustrating how forecasts, alerts, SHAP and reports fit an energy-management workflow.

**Not intended:** safety-critical dispatch, automated breaker/generator control,
settlement or billing, or operational decisions on a real installation without
retraining and validation on that installation's data.

## Security and privacy

- No real installation data, coordinates precise enough to be sensitive, or classified
  information is used. Site coordinates are approximate public locations.
- The demo is read-only and unauthenticated; production requires authentication, RBAC,
  audit logging, TLS, and network isolation.
- The model artifacts contain no personal data.

## Reproduction

```powershell
python src/fetch_weather.py        # public weather data (already cached)
python src/generate_load.py        # synthetic facility load
python src/preprocess.py           # feature engineering
python src/train_all_sites.py      # XGBoost + residual LSTM per site
python src/build_forecasts.py      # replay tables, SHAP, summaries
```

Artifacts: `config/xgb_<site>.pkl`, `config/lstm_<site>.pt`,
`config/scaler_<site>.pkl`, `config/rscaler_<site>.pkl`,
`data/processed/replay_<site>.csv`, `data/processed/shap_<site>.npz`.
